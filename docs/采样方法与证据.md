# 采样方法与证据

本版采样日期为 **2026-10-09**，主要抓取时间为 **09:41 UTC（北京时间 17:41）**。
这是一个有来源的观察样本，适合产生选题与展示假设；不用于证明增长因果、产品质量或市场规模。

## GitHub 样本怎么来

读取 [日榜](https://github.com/trending?since=daily)、[周榜](https://github.com/trending?since=weekly)、
[月榜](https://github.com/trending?since=monthly)，共捕获 9、11、24 个条目。
这是当时页面返回的条目，不宣称覆盖全部 GitHub 仓库。跨时间窗会出现同一个项目，44 是条目数而非去重项目数。

每条记录包含仓库、榜单页面顺序、累计 Stars、榜单标注的时间窗增星、页面来源与 UTC 抓取时间，保存在
[trending_snapshot.json](../data/trending_snapshot.json)。
页面顺序只表示那张页面上的位置；GitHub 未在本样本提供一个可据此计算“行业排名”的公开评分。

随后从公开仓库 REST API 核验 16 个代表项目，保留描述、累计 Stars、Forks、Topics、创建与更新时间、许可标识，见
[repository_evidence.json](../data/repository_evidence.json)。
`status: verified` 表示元数据请求成功，不表示独立验证了项目作者的性能、隐私或安全承诺。
API 与榜单抓取时间相差几秒，累计星数有小幅变化属于正常现象；报告分别使用两者的原始字段。

编辑根据项目用途归纳十个方向，分类配置在 [directions.json](../data/directions.json)。
分类可以交叉，例如 Skills 与可编辑图形、编码工具与多 Agent。
编号方便阅读，不按累计星数或日/周/月混合增星排序；没有把某一项目的涨幅推算成整个方向的增长。

## 高互动帖子怎么来

从公开搜索寻找跨方向的 2026 年 Show HN 技术发布案例，再用 HN 官方 item API 核验。
本版保留 11 篇积分达到 100 以上、能够阅读介绍与讨论的目的性样本；包含 1 月至 8 月较早案例和 9 月案例。
没有建立所有帖子总体，也没有随机抽样，所以不能称作“全网最高赞十大帖子”。

[post_evidence.json](../data/post_evidence.json)保存每篇的发布时间、官方 API、积分、评论数、内容与反馈来源。
`score` 是 HN 帖子积分，`descendants` 是评论及回复数量，均不等于 GitHub Stars。
高互动不代表全部正面反馈；本版同时记录性能比较、推荐时效和界面可用性等质疑。

## 哪些结论有证据，哪些只是建议

| 结论 | 依据与边界 |
|---|---|
| 某仓库在采样时有多少累计星 | 官方 API 元数据，随时间变化 |
| 某项目榜单上标注多少近期增星 | 对应日/周/月页面快照，不混合排名 |
| 某帖发布时间、积分与评论数 | 官方 HN item API；为采样时计数 |
| 项目和帖子具体展示什么 | 作者介绍与公开讨论；产品承诺未独立复测 |
| 某种展示方法可能改善理解与试用 | 编辑观察和待验证假设 |
| 某种方法必定带来 Stars 增长 | 本版没有这类证据，也不作此结论 |

## 如何更新

1. 另存新的榜单和 API 快照，记录实际采样时间，保留旧版本或提交历史。
2. 查验帖子原文与现行社区规则，区分近期案例与历史参考。
3. 重新审视方向分类，不机械沿用旧“十大”。
4. 更新 JSON 后运行 `python scripts/build_reports.py`，再运行测试与包验证。
5. 阅读报告，确认数字、日期、分类及引用仍然对应当前证据。

附带的 `github_snapshot.py` 只负责单个公开仓库的计数快照，不抓取热门榜单，也不自动发布内容。
仓库维护者可另外查看 [GitHub 流量数据](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-traffic-to-a-repository)，
其访问、克隆和来源窗口与 Stars 指标不同；参见[指标说明](../skills/github-project-outreach/references/measurement.md)。
